# 新前端执行规则

适用目录：`General.Frontend/`。本目录承接商城及其他 B 端业务的通用管理基建，直接迁入 Chao_fisemap 作为现有前端底座，保留其页面结构、组件、布局和样式，主要适配 General.Admin 后端。

## 开始与恢复

1. 首次实施先读 `../.doc/08-前端重建/00-开始这里.md`、`03-执行规则与完成标准.md`、`05-进度台账.md`。
2. 按 `02-分阶段待办清单.md` 选择依赖已完成的第一个未完成步骤；续工时先核对上一步记录与实际文件。
3. 每次只推进一个步骤；读对应 Goal、契约矩阵和相关源文件即可，不重复扫描整仓和参考源全部页面。
4. 先写步骤记录中的目标、范围、输入及开工基线，再修改代码。
5. 完成实现后执行本步骤检查，补齐记录，更新清单及台账，再开始下一步。
6. 当前进度以 `.doc/08-前端重建/05-进度台账.md` 和主清单为准：独立工程已建立，G02-01已直接迁入Chao_fisemap前端底座；不得把未接真实API/权限的演示路由误报为业务完成。
7. 全部实施范围为G00–G13、59步：平台基础和用户授权之后，依次覆盖平台治理、Integration、Project、Business、AI、共享样板、全量回归及仓库入口切换；不要把旧的G00–G08/29步草案当作当前计划。
8. 用户已授权持续完成整套重建并在安全隔离环境验证API/浏览器。换模型不代表等待或重新规划；按进度台账继续。遇真实测试环境阻塞时记录原因并继续独立工作。

## 工程边界

- 独立 Vue 3 + TypeScript + Vite 应用，不放入旧 `General.Web` workspace。
- Vue Router 管路由；优先沿用迁入源码已有状态方案。接入真实会话/权限时先核实现有实现，再按实际需要扩展；局部页面状态留在原页面或 composable。
- UI 行为基于 Reka UI 等底层库，只允许 `components/ui` 包装；业务 feature 从内部 UI 公开入口导入。
- 禁止 `@vben/*`、`@vben-core/*`、Ant Design Vue、旧 VXE 适配器和旧工程跨目录运行时依赖。
- Chao_fisemap 的完整应用源码、组件、布局、路由、页面和样式是本工程直接底座；不得另起一套等价页面或视觉系统。
- 迁入页面中的 fixture、本地保存、硬编码身份和演示通知必须标记为未接入真实后端；完成真实 DTO/API/权限适配前不得作为生产菜单入口。
- 只迁移前端运行所需文件；参考仓库的复刻验收脚本、生成输出、进度目录和项目级 AGENTS 不作为运行时迁入。
- 表格和表单先解决用户管理实际需求，复用经真实页面验证的结构，不做万能 JSON 页面引擎。
- 采用 `src/api/core`、`src/features`、`src/components/ui`、`src/components/page`、`src/components/layout`、`src/router`、`src/stores`、`src/styles` 边界，详见总规划。
- CodeGraph 覆盖时优先使用；未覆盖时用 `rg` 和定向读取。不编辑 `.codegraph`。

## 代码与界面

- TypeScript strict；2 空格、单引号；禁止新增 `any`、空点击、依文案推断动作和伪造成功状态。
- API 类型保持 `namespace XxxApi {}`，逐字段对照后端 DTO；空值、枚举、分页和排序按接口实际能力处理。
- 所有用户可见文字、业务注释和提交说明使用中文；技术标识符使用英文。
- 用户明确要求 Chao_fisemap 原视觉保持不变。本重建不得修改或新增CSS、CSS Modules、Tailwind样式、主题token、布局规则或shell样式；适配集中在 API、数据、身份、权限和导航行为。
- 本轮是把现有前端接上 General.Admin，不是重写或重新设计界面：已有页面、组件和交互直接沿用，改动优先落在 API 客户端、DTO映射、权限和路由。需要补齐业务操作时，在最近的现有页面结构里复用已有控件，不另造等价页面、不改迁入结构、不写新样式。若现有控件组合无法表达某项契约，记录具体缺口并交由用户决定，不自行改版。
- 参考源中的硬编码用户、商品首页、试用条、商标、Demo 通知及本地 fixture 可以暂留作为模板源；必须清晰标为演示/未接入，真实生产入口启用前再接入真实身份、菜单和接口，不得伪装成已落库。
- 对迁入源文件先维持原样；只在当前实现任务要求改动时评估是否拆分，避免为了行数或风格偏好进行无关重构。新建/大幅修改的 Vue 文件接近 350 行时按职责评估拆分。
- 通用 Dialog、Drawer、Select、Dropdown、Toast 等使用内部封装，补齐键盘、ARIA、焦点返回及 reduced motion。
- 保留迁入源的现有列表和全局布局样式；浏览器验证发现兼容问题时先从数据、行为和入口边界排查，不自行改版或新增局部样式。

## 契约与权限

- 通用请求集中处理 `ApiResponse<T>` 和 ABP 错误；文件流及上传独立按实际响应处理。
- 当前没有已核实的 refresh 端点；401 清理会话并回登录，普通 403 保留会话并提示无权限。
- 登录失败也可能返回 403，登录页按实际响应显示错误；不得把所有 403 当成会话过期。
- 权限码由后端返回，菜单组件字符串经本地白名单适配。未知组件关闭入口并记录，禁止动态执行远端代码。
- 默认只装配本轮已实现、已验收的模块；未实现菜单不开放，管理页应说明兼容状态。
- 页面隐藏按钮不能代替后端鉴权；角色菜单授权、数据范围、租户上下文都必须实际验证。
- 默认令牌只在会话内使用，可采用 sessionStorage 恢复刷新后的会话；禁止持久化密码或输出令牌。
- 无真实接口时记录缺口，开发样例明确标识并隔离，正式业务页面不以 localStorage 冒充保存。
- 当前General.Admin源码尚无商品/SKU/库存/购物车/订单/支付专用契约；商城专属页面必须等待真实Contracts/API，不创建虚构业务CRUD。

## 验证与记录

- 迁入源代码使用源项目 CSS Module 审计器、参考 Prettier配置、架构边界检查、Vite build；Oxlint按本步新增/适配文件范围执行。Tailwind v4的`@apply`/`@reference`不直接套用standard Stylelint全量规则；新样式按适用规则单独审查。
- 每步运行对应检查；共享 API/类型/组件变更跑typecheck，阶段交付跑build，页面变更验证浏览器关键路径。迁入基线的既有页面若存在编译问题，必须记入执行台账；每个启用的General.Admin页面在上线入口前单独修复并类型检查，G12前全量typecheck必须通过。
- 关键认证、请求及权限逻辑需要有效的自动化验证；不写只复述实现或只验证存在的测试。

- 原参考项目只读；停止运行的服务、端口及临时账号应在台账记录。不得操作生产数据作为验收。
