# 04 分期建设与研发准备

## 1. 修订说明

本文按当前系统真实建设顺序重写，作为“从零设计时如何分期”的正式说明。

原先文档中把 AI 写成四期预留、把 OA/协同写成五期的口径已不再作为正式路线。当前正式路线为：

- 四期：PMP 项目管理闭环强化
- 五期：AI 智能能力区
- 六期：外部系统集成区
- 七期：项目 CLI Skill 化

## 2. 分期总原则

分期不是为了写计划书，而是为了回答一件事：  
先把哪一层做成可靠基线，后面才能继续长。

## 3. 第一期：平台中心

### 3.1 目标

- 把用户、角色、菜单、日志、监控、文件这些系统底座先做稳

### 3.2 当前承接内容

- 组织架构
- 用户管理
- 角色权限
- 菜单管理
- 租户管理
- 文件管理
- 审计日志
- 系统监控
- 定时任务
- 个人中心

### 3.3 设计意义

一期不是业务功能堆砌阶段，而是平台治理阶段。

## 4. 第二期：项目执行区

### 4.1 目标

- 把项目执行真正搬进系统
- 形成以 `项目详情` 为中心的执行驾驶舱

### 4.2 当前承接内容

- 项目列表
- 项目详情
- 与我相关
- PM 工作台
- PMO 执行总览

## 5. 第三期：经营管理区

### 5.1 目标

- 把经营管理从零散台账升级为清晰的信息架构
- 形成经营总览、项目经营、报表中心三类稳定入口

### 5.2 当前承接内容

- 经营总览
- 项目经营
- 报表中心

## 6. 第四期：PMP 项目管理闭环强化

### 6.1 目标

- 在项目详情和经营链稳定后补齐 PMP 基础能力
- 让项目过程从“展示信息”升级为“可计划、可控制、可追踪、可复盘”

### 6.2 当前承接内容

- 项目章程
- WBS 与任务依赖
- RAID 风险管理
- 质量管理
- 变更请求与影响分析
- 基线与 EVM 快照
- 结构化项目角色
- 经营链 CRUD 与执行跟踪
- 会议、报告、资源、收尾等增强项

### 6.3 设计意义

四期是五期 AI 的数据前置条件。没有 WBS、风险、质量、变更、基线、EVM、会议和报告这些结构化对象，AI 只能做文本拼接，不能做可信管理辅助。

## 7. 第五期：AI 智能能力区

### 7.1 目标

- 新增独立 AI 模块
- 支持多 Provider、多模型、MCP、提示词、助手、会话、记忆、场景模板、用量和审计
- 为 PM、PMO、项目成员、经营管理人员提供澄清、规划、总结、分析、报告和问答能力

### 7.2 当前规划入口

- `.doc/05-五期建设/01-AI模块建设总规划.md`
- `.doc/05-五期建设/02-AI模块执行清单.md`

## 8. 第六期：外部系统集成区

### 8.1 目标

- 新增独立 Integration 模块
- 接入飞书、钉钉、企业微信等企业协同系统
- 实现组织用户同步、账号绑定、个人通知、群通知、机器人卡片、会议记录、风险和行动项同步

### 8.2 当前规划入口

- `.doc/06-六期建设/01-外部系统集成模块建设总规划.md`
- `.doc/06-六期建设/02-外部系统集成执行清单.md`

## 9. 第七期：项目 CLI Skill 化

### 9.1 目标

- 不新增业务模块，只新增 AI 可读的操作说明和 Skill 包
- 将项目查询、项目报告、风险分析、会议纪要、经营分析等高频操作沉淀成通用 SKILL.md
- 面向 OpenCowork、Codex 和内部 AI 保持通用结构，方便后续接入不同 Agent
- 为未来 MCP 或更强工具调用预留升级路径，但本期不实现 MCP runtime

### 9.2 当前规划入口

- `.doc/07-七期建设/01-项目CLI-Skill建设总规划.md`
- `.doc/07-七期建设/02-项目CLI-Skill执行清单.md`

## 10. 研发准备方法

如果以后重新从零设计类似系统，建议准备材料的顺序是：

1. 产品边界
2. 分期策略
3. 角色与高频场景
4. 页面信息架构
5. 核心对象与字段
6. 接口边界
7. 指标和预警口径
8. 权限、审计和安全边界
9. 外部系统边界
10. 运维、成本和可观测性
11. AI 可调用 Skill 和操作规范

## 11. 当前结论

当前这一套分期已经经过项目实现反向验证，优先级顺序应保持为：

- 先平台
- 后执行
- 再经营
- 补 PMP 闭环
- 再做 AI
- 再打通外部系统
- 最后沉淀项目 CLI Skill
