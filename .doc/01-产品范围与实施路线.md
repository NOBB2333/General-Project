# 01 产品范围与实施路线

## 1. 修订说明

本文保留原编号，但内容按当前项目实现、PMP 基础能力建设结果，以及五期/六期/七期新规划重新修订。

当前不再把它当成“纯概念稿”，而是当成：

- 从零设计这套系统时的总入口
- 后续继续演进时的范围控制依据
- 判断新能力应该进入哪个模块的边界依据

## 2. 产品定义

产品名称：`General Admin 企业内部项目管理平台`

这是一个面向企业内部使用的私有化项目管理系统，目标不是做一个大而全的后台，也不是做低代码平台，而是围绕企业项目全过程，形成七期逐步建设的统一平台：

1. 一期：平台中心
2. 二期：项目执行区
3. 三期：经营管理区
4. 四期：PMP 项目管理闭环强化
5. 五期：AI 智能能力区
6. 六期：外部系统集成区
7. 七期：项目 CLI Skill 化

## 3. 先解决什么问题

从零设计这个系统时，优先解决的不是“模块齐不齐”，而是下面几类真实问题：

- 权限、菜单、组织、日志、监控缺少统一平台承接
- 项目推进过程分散在 Excel、聊天和口头沟通中
- PM 很难在一个系统里同时看进度、任务、问题、里程碑、风险和工时
- PMO 很难稳定查看多项目状态、进度偏差、成本偏差和异常项目
- 经营数据容易散在合同、回款、项目台账里，缺少总览和下钻
- PMP 管理过程缺少结构化数据，难以沉淀可复用的项目管理资产
- 后续 AI 能力缺少稳定的数据、权限、审计和工具边界
- 外部协同系统中的通知、会议、群消息、组织用户数据无法稳定回流
- 项目管理能力需要沉淀成 AI 可读的操作规范，方便后续 OpenCowork、Codex 或内部 AI 调用

## 4. 当前产品边界

本产品当前要做：

- 平台治理与共享能力
- 项目执行主线
- 经营管理主线
- PMP 项目管理闭环
- AI 辅助管理能力
- 飞书、钉钉、企业微信等外部系统集成能力
- 项目 CLI Skill 化与 AI 操作说明沉淀

本产品当前不做：

- 完整财务核算系统
- 客户门户
- 供应商门户
- 低代码万能平台
- 通用聊天机器人平台
- 通用 Agent 编程平台
- 通用 Skill 市场
- 独立移动端主产品

## 5. 当前三区与后续能力区结构

### 5.1 平台中心

承接通用治理能力：

- 组织架构
- 用户管理
- 角色权限
- 菜单管理
- 租户管理
- 文件管理
- 审计日志
- 系统监控
- 定时任务
- 个人中心

### 5.2 项目执行区

承接项目全过程执行能力：

- 项目列表
- 项目详情
- 与我相关
- PM 工作台
- PMO 执行总览

### 5.3 经营管理区

承接项目经营与经营预警能力：

- 经营总览
- 项目经营
- 报表中心

### 5.4 AI 智能能力区

五期新增独立模块，不混入 Platform、Project 或 Business。

承接：

- AI Provider 与模型配置
- AI 会话与项目问答
- 澄清模式
- 规划模式
- 项目报告生成
- 风险与问题分析
- 会议纪要整理
- 项目知识与记忆
- MCP 工具接入与能力暴露
- AI 使用量、成本、权限和审计

### 5.5 外部系统集成区

六期新增独立模块，不把飞书、钉钉、企业微信等连接器散落到 Platform 或 Project 中。

承接：

- 飞书、钉钉、企业微信连接器
- 外部账号绑定
- 组织与用户同步
- 群与机器人配置
- 项目通知推送
- 风险、会议、行动项同步
- 外部 Webhook 回调
- 消息投递记录、重试、死信和审计

### 5.6 项目 CLI Skill 化

七期新增能力封装层，不新增业务模块，不替代五期 AI 模块和六期 Integration 模块。

承接：

- General Admin 项目管理操作 Skill
- 项目查询、报告、风险、会议、经营分析等 SKILL.md
- 面向 OpenCowork、Codex 和内部 AI 的通用操作说明
- 项目 CLI 使用规范和命令约定
- Skill 安全边界、审批边界和上下文要求
- Skill 包版本、分发和验收清单

## 6. 实施路线

### 6.1 一期：平台中心

先把系统底座和治理能力做稳，不让后续业务区各自重复造权限、菜单、日志和监控。

### 6.2 二期：项目执行区

把项目执行真正搬进系统，形成以 `项目详情` 为中心的执行驾驶舱。

### 6.3 三期：经营管理区

把经营管理区从零散台账收敛成 `经营总览 / 项目经营 / 报表中心`。

### 6.4 四期：PMP 项目管理闭环强化

在项目详情与经营链稳定后，补齐章程、WBS、依赖、RAID、质量、变更、基线、EVM、会议、报告、资源和收尾等 PMP 基础能力。

### 6.5 五期：AI 智能能力区

在前四期沉淀了项目执行、经营、风险、质量、会议、文档和绩效数据后，通过独立 AI 模块实现澄清、规划、总结、分析、报告、知识问答和受控工具调用。

### 6.6 六期：外部系统集成区

在系统内部管理闭环稳定后，接入飞书、钉钉、企业微信等企业常用协同系统，实现组织用户同步、个人与群通知、会议记录回流、风险和行动项同步。

### 6.7 七期：项目 CLI Skill 化

在 AI 和外部集成能力稳定后，把 General Admin 的高频项目管理操作沉淀成通用 Skill 包，让 OpenCowork、Codex 或内部 AI 能按稳定说明调用项目 CLI、读取上下文、生成报告和执行受控操作。

## 7. 当前结论

这个项目的正确路线不是“一开始把所有模块都铺开”，而是：

- 先平台
- 后执行
- 再经营
- 补 PMP 管理闭环
- 接 AI 辅助能力
- 打通企业外部协同系统
- 最后沉淀 AI 可调用的项目 CLI Skill

五期和六期必须新增独立模块。AI 与外部集成可以复用平台的文件、通知、审计、定时任务等基础能力，但不能把自身领域对象混入 Platform、Project 或 Business。

七期不新增业务模块，只沉淀 Skill、命令规范和操作手册，服务后续 AI 调用和团队交付复用。
