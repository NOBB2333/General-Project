# 六期建设总规划：外部系统集成区

> 版本：v1.0  
> 状态：代码闭环已落地，真实租户验收待环境联调  
> 定位：独立 Integration 模块，不混入 Platform、Project、Business

## 1. 建设背景

项目管理系统要真正进入企业日常工作，需要和企业常用协同系统打通。飞书、钉钉、企业微信等系统承担了组织通讯、群协作、会议、审批、个人提醒和机器人消息的入口。

六期建设的目标不是把 General Admin 做成完整 OA，也不是复制飞书/钉钉/企业微信，而是让项目管理系统与外部协同系统形成稳定连接：

- 内部项目数据能推送到个人和群
- 外部会议、群消息和交互回调能回流
- 外部组织和用户能同步
- 风险、会议记录、行动项、任务提醒能形成闭环

OpenCowork 的 `ChannelManager` 和内置消息平台插件可以作为重要参考。它将飞书、钉钉、企业微信、微信、QQ、Telegram、Discord、WhatsApp 等平台抽象为 Channel Provider，并通过统一工具描述提供发送消息、回复消息、获取群消息、获取群列表等能力。General Admin 不照搬 Electron 插件运行时，但应吸收“连接器注册 + 配置 Schema + 工具能力清单 + 投递记录”的设计。

|---|---|---|

## 4. 设计原则

1. 外部系统集成是独立模块，不是 Platform 附属配置。
2. Integration 负责连接、映射、同步、投递、重试、审计。
3. Project/Business 负责业务数据和业务口径。
4. Platform 可提供通知、定时任务、审计、文件等基础能力。
5. 外部系统回调必须签名校验、幂等处理、租户隔离。
6. 外部账号不能长期靠姓名匹配，必须建立绑定和映射。
7. 消息发送必须有投递记录和失败重试。
8. 群通知和个人通知必须可配置，不做硬编码。
9. 连接器能力应像 OpenCowork Channel Provider 一样显式声明，不靠页面临时拼接。
10. Integration 可以被 AI 和 Skill 调用，但外部系统密钥、投递和回调始终归 Integration 管。

## 5. OpenCowork Channel 架构参考

OpenCowork 中消息平台能力由 `ChannelManager` 和 `ChannelProviderDescriptor` 管理。每个连接器声明：

- provider type
- display name
- icon
- builtin 标记
- config schema
- 支持的工具能力

General Admin 六期建议映射为：

| OpenCowork Channel 点 | General Admin 落地方式 |
|---|---|
| ChannelProviderDescriptor | `IntegrationConnector` 定义连接器类型和能力 |
| configSchema | `IntegrationTenantConfig` 定义租户级配置字段和密钥 |
| COMMON_PLUGIN_TOOLS | `IntegrationConnectorCapability` 或连接器能力枚举 |
| Feishu/DingTalk/WeCom tools | 飞书、钉钉、企业微信连接器适配服务 |
| PluginSendMessage | `IntegrationDispatchService` 统一投递 |
| PluginListGroups | 群绑定、群列表同步和项目群映射 |
| PluginGetGroupMessages | 群消息回流和 Webhook 事件处理 |

边界：

- OpenCowork Channel 是 Agent 插件；General Admin Integration 是企业系统连接器。
- 连接器负责真实投递、验签、重试、死信和审计。
- AI 模块只能通过受控服务请求草稿或投递建议，不能直接保存连接器密钥。
- 七期 Skill 只能描述如何使用 CLI/API 查询或触发集成操作，不实现连接器协议。

## 6. 连接器范围

### 6.1 第一优先级

| 连接器 | 主要用途 |
|---|---|
| 飞书 / Lark | 组织用户同步、机器人消息、互动卡片、会议记录、日程 |
| 钉钉 | 组织用户同步、工作通知、机器人消息、审批/待办 |
| 企业微信 | 组织用户同步、应用消息、群机器人、客户企业常用入口 |

### 6.2 第二优先级

| 连接器 | 主要用途 |
|---|---|
| 微信公众号 | 对外通知、低频消息触达 |
| 邮件 | 报表分发、审批提醒、异常通知 |
| 短信 | 高优先级异常提醒 |

### 6.3 后续扩展

| 连接器 | 主要用途 |
|---|---|
| Teams | 外企或跨国团队协作 |
| Slack | 技术团队协作 |
| Jira / GitLab / GitHub | 研发工具链扩展 |

## 14. 验收标准

- Integration 模块有独立菜单、权限、API 和数据库表。
- 至少完成飞书一个连接器 MVP。
- 至少支持用户绑定、部门绑定和项目群绑定。
- 至少支持个人消息和项目群消息。
- 任务到期、风险到期、会议纪要至少各有一类通知规则。
- Webhook 回调有签名校验和原始事件记录。
- 投递记录可查询，失败可重试。
- 外部事件处理具备幂等。
- AppSecret 不明文落库。
- 敏感经营字段默认不外发。
- 每个连接器必须声明配置字段和能力清单。
- AI 和 Skill 只能通过 Integration 受控服务触发投递或查询日志。
