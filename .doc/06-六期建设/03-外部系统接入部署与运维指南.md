# 六期外部系统接入部署与运维指南

> 状态：首版已落地  
> 范围：飞书、钉钉、企业微信接入部署、回调域名、内网代理、密钥和运维检查。  
> 原则：配置放租户，密钥加密保存；真实消息和回调必须走 Integration 模块，不允许 AI 或 Skill 绕过。

## 1. 通用接入拓扑

```text
企业平台（飞书/钉钉/企业微信）
        │
        │  HTTPS 回调 / Token / 消息发送 / 组织同步
        ▼
公网域名 / 网关 / 反向代理
        │
        ▼
General.Admin.HttpApi.Host
        │
        ├─ IntegrationConnector
        ├─ IntegrationTenantConfig
        ├─ IntegrationDeliveryRecord
        ├─ IntegrationWebhookEvent
        └─ IntegrationSyncJob / IntegrationSyncRecord
```

部署要求：

- HttpApi Host 必须暴露稳定 HTTPS 域名。
- 回调地址必须能被企业平台访问。
- AppSecret、Token、Webhook Secret 不允许明文写入文档、日志或前端。
- 多租户环境下，每个租户独立配置连接器。
- 消息发送、同步任务、Webhook 事件都必须可审计。

## 2. 回调域名配置

推荐回调域名：

```text
https://<public-domain>/api/app/integration/webhooks/<connector-code>/receive
```

首版已具备内部 Webhook 事件治理能力。公开回调入口和真实验签接入时，必须满足：

- 只允许 HTTPS。
- 反向代理保留原始请求体，不能改写 JSON。
- 保留关键请求头，用于验签和审计。
- 回调入口必须写入 `IntegrationWebhookEvent`。
- 解析失败、验签失败、重复事件都必须保留原始事件。
- 幂等键优先使用平台事件 ID；没有事件 ID 时使用请求摘要生成。

当前已落地匿名 POST 回调入口：

```text
POST /api/app/integration/webhooks/{connectorCode}/receive
```

已接入能力：

- 飞书、钉钉、企业微信基础 JSON 事件接收。
- 飞书 Verification Token 校验。
- 钉钉 callbackToken + timestamp + nonce + body 的 SHA1 校验。
- 企业微信 token + timestamp + nonce + body/encrypt 的 SHA1 校验。
- 事件类型、幂等键、动作码、业务 Key 标准化入库。
- 飞书 URL 验证 `challenge` 直出。

仍需真实联调补齐：

- 飞书、钉钉、企业微信加密回调解密。
- 钉钉、企业微信 GET URL 验证完整流程。
- 真实卡片按钮和群事件回流验收。

Nginx 示例：

```nginx
location /api/app/integration/webhooks/ {
    proxy_pass http://general-admin-api;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    client_max_body_size 10m;
}
```

## 3. 内网代理配置

如果 General Admin 部署在内网，但企业平台要求公网回调，有三种方案：

| 方案 | 适用场景 | 注意事项 |
|---|---|---|
| 公网反向代理 | 标准私有化部署 | 推荐方案，便于证书和审计治理 |
| API 网关转发 | 企业已有统一网关 | 网关必须保留原始请求体和签名头 |
| 内网穿透 | 测试联调 | 仅用于测试，不建议生产使用 |

出站访问要求：

- 允许 HttpApi Host 访问飞书、钉钉、企业微信 OpenAPI 域名。
- 如果企业要求统一出口，需在运行环境配置 `HTTP_PROXY` / `HTTPS_PROXY` 或平台网关。
- 代理层不能记录 AppSecret、Token 和消息正文中的敏感字段。

## 4. 飞书接入步骤

### 4.1 平台准备

1. 在飞书开放平台创建企业自建应用。
2. 获取 `AppId`、`AppSecret`。
3. 开启通讯录权限：
   - 部门读取
   - 用户读取
4. 开启消息发送权限：
   - 给用户发送消息
   - 给群发送消息
   - 发送富文本 / Markdown / 互动卡片
5. 如需回调，配置事件订阅和回调地址。

### 4.2 General Admin 配置

1. 进入 `外部系统集成区 / 连接器配置`。
2. 选择飞书连接器。
3. 填写 AppId、AppSecret、回调路径和扩展配置。
4. 保存后执行连接测试。
5. 执行测试发送，确认个人消息或群消息可达。
6. 配置同步任务：
   - `Department`：飞书部门同步
   - `User`：飞书用户同步
7. 执行手动同步，检查同步记录。
8. 在外部账号绑定页处理自动匹配和冲突。

### 4.3 验收点

- Token 获取成功。
- 连接测试成功。
- 个人消息发送成功。
- 群消息发送成功。
- 互动卡片发送成功。
- 部门同步记录成功落库。
- 用户同步记录成功落库。
- 外部账号能绑定内部用户。
- 投递日志和同步记录可追踪。

## 5. 钉钉接入步骤

### 5.1 平台准备

1. 在钉钉开放平台创建企业内部应用。
2. 获取 `AppKey`、`AppSecret`、`AgentId`。
3. 开启通讯录读取权限。
4. 开启工作通知发送权限。
5. 如需群机器人，配置机器人 Webhook 和签名密钥。
6. 如需回调，配置事件订阅和回调地址。

### 5.2 General Admin 配置

1. 进入 `外部系统集成区 / 连接器配置`。
2. 选择钉钉连接器。
3. 填写 AppKey、AppSecret、AgentId、机器人配置和回调路径。
   - `连接配置` 示例：
     ```json
     {
       "appKey": "ding-app-key",
       "agentId": "123456",
       "robotWebhook": "https://oapi.dingtalk.com/robot/send?access_token=xxx"
     }
     ```
   - `连接密钥` 可直接填写 AppSecret。
   - 如果同一个连接器还需要钉钉加签群机器人，可在 `连接密钥` 中填写加密 JSON：
     ```json
     {
       "appSecret": "ding-app-secret",
       "robotSecret": "SECxxx"
     }
     ```
   - `robotWebhook` 也可只填写机器人 `access_token`，系统会自动拼接钉钉默认机器人地址。
4. 保存后执行连接测试。
5. 执行测试发送，确认工作通知或群机器人消息可达。
6. 配置同步任务：
   - `Department`：钉钉部门同步
   - `User`：钉钉用户同步
7. 执行手动同步，检查同步记录和外部账号池。

### 5.3 验收点

- Token 获取成功。
- 工作通知测试发送成功。
- 群机器人测试发送成功。
- 部门和用户同步成功。
- 回调事件能写入 Webhook 事件中心。

## 6. 企业微信接入步骤

### 6.1 平台准备

1. 在企业微信管理后台创建自建应用。
2. 获取 `CorpId`、`AgentId`、`Secret`。
3. 开启通讯录同步权限。
4. 配置可信 IP 或企业可信域名。
5. 如需群机器人，创建群机器人 Webhook。
6. 如需回调，配置 Token、EncodingAESKey 和回调地址。

### 6.2 General Admin 配置

1. 进入 `外部系统集成区 / 连接器配置`。
2. 选择企业微信连接器。
3. 填写 CorpId、AgentId、Secret、群机器人配置和回调路径。
   - `连接配置` 示例：
     ```json
     {
       "corpId": "wwxxxxxxxx",
       "agentId": "1000002",
       "robotWebhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"
     }
     ```
   - `连接密钥` 可直接填写 CorpSecret。
   - 如需后续扩展多密钥，可在 `连接密钥` 中填写加密 JSON：
     ```json
     {
       "corpSecret": "wecom-corp-secret"
     }
     ```
   - `robotWebhook` 也可只填写机器人 `key`，系统会自动拼接企业微信默认机器人地址。
4. 保存后执行连接测试。
5. 执行测试发送，确认应用消息或群机器人消息可达。
6. 配置同步任务：
   - `Department`：企业微信部门同步
   - `User`：企业微信用户同步
7. 执行手动同步，检查同步记录和外部账号池。

### 6.3 验收点

- Token 获取成功。
- 应用消息测试发送成功。
- 群机器人测试发送成功。
- 部门和用户同步成功。
- 回调事件能写入 Webhook 事件中心。

## 7. 密钥与安全

## 6.5 集成沙箱验收

集成沙箱连接器用于本地、测试和预发布环境验收 Integration 主链路，不依赖飞书、钉钉、企业微信真实租户。

连接器编码：

```text
sandbox
```

租户配置示例：

```json
{
  "acceptMessage": true,
  "forceFailure": false,
  "echoPrefix": "[验收] "
}
```

验收范围：

- 连接测试成功或按 `forceFailure` 返回失败。
- 测试消息投递写入 `IntegrationDeliveryRecord`。
- 部门同步写入 `IntegrationDepartmentBinding`。
- 用户同步写入 `IntegrationExternalAccount`。
- 群同步和会议同步复用 `IntegrationSyncImportService`。
- Webhook JSON 事件解析为标准事件类型、动作码、业务 Key 和幂等键。
- 重复 Webhook 返回同一事件记录，验证幂等生效。

沙箱不能替代真实平台验收。飞书、钉钉和企业微信仍需要使用真实企业租户、真实账号、真实群、真实回调域名做最终验收。

当前已落地：

- AppSecret 加密保存。
- Token 不明文返回前端。
- 连接器支持独立密钥轮换，轮换后自动清空缓存 Token 并进入待重测状态。
- 投递日志保留状态、耗时和错误摘要。
- 投递日志支持按筛选条件导出 CSV 审计文件。
- Webhook 原始事件保留处理状态和幂等键。
- Webhook 来源 IP 白名单可通过 `Admin.Platform.IntegrationWebhookIpWhitelist` 配置，支持 IP 和 CIDR，空值表示不限制。
- Webhook 接收支持请求频控，配置项为 `Admin.Platform.IntegrationWebhookRequestLimitPerMinute`，默认每分钟 120 次，设置为 `0` 可关闭。
- 外部消息发送支持目标级频控，配置项为 `Admin.Platform.IntegrationMessageSendLimitPerMinute`，默认每分钟 60 次，设置为 `0` 可关闭。
- 连接器、投递记录和 Webhook 事件已具备租户隔离回归测试，运维排查跨租户问题时应优先确认请求上下文中的租户标识。

后续需要继续建设：

- 加密回调解密和真实平台回调验收。

当前 Webhook 解析结果：

- 卡片按钮字段会统一解析到 `ActionCode`，常见路径包括 `action`、`actionCode`、`event.action.value.action`、`EventKey`。
- 业务主键会统一解析到 `BusinessKey`，常见路径包括 `businessKey`、`projectId`、`event.action.value.project_id`。
- 群消息文本如果符合 `/command businessKey`、`!command businessKey` 或 `！command businessKey`，会解析为 `ActionCode=command.<command>`、`BusinessKey=<businessKey>`。

## 8. 通知规则派发

通知规则测试和业务任务触发统一走：

```text
POST /api/app/integration/notification-rules/dispatch
```

请求体示例：

```json
{
  "eventCode": "project.weekly-report.due",
  "occurredAt": "2026-06-26T10:00:00Z",
  "variablesJson": "{\"recipient\":{\"userIds\":[\"<internal-user-id>\"]},\"report\":{\"name\":\"本周项目周报\",\"weekStartDate\":\"2026-06-22\"}}"
}
```

接收人规则支持三种模式：

```json
{
  "mode": "Direct",
  "targetIds": ["ou_xxx"],
  "targetType": "OpenId"
}
```

```json
{
  "mode": "InternalUsers",
  "userIdsPath": "recipient.userIds",
  "targetType": "OpenId"
}
```

```json
{
  "mode": "ProjectGroup",
  "projectIdPath": "project.id",
  "objectType": "Project",
  "targetType": "Chat"
}
```

说明：

- `Direct` 适合固定管理员、固定群或测试规则。
- `InternalUsers` 会通过内部用户 ID 查询已绑定的外部账号。
- `ProjectGroup` 会通过项目 ID 查询已绑定的外部群。
- 派发成功或失败都会写入投递日志。
- 项目类和经营类提醒都会提供 `project.detailUrl`，模板可生成“查看项目详情”文本链接或卡片按钮。
- PM 周报提醒定时任务已触发 `project.weekly-report.due`，真实投递取决于是否配置了对应通知规则和账号绑定。
- 项目提醒扫描任务 `project-reminder-notification` 已触发：
  - `project.task.due`：任务计划结束日期在 3 天内。
  - `project.task.overdue`：任务计划结束日期早于今天。
  - `project.risk.due`：风险计划解决日期在 7 天内。
  - `project.risk.high`：风险分值不低于 16，或等级为 P0/P1。
  - `pmo.governance.action`：任务逾期或高风险项需要 PMO 治理关注。
  - `project.meeting.reminder`：会议时间在 24 小时内。
  - `project.meeting.minutes.distribute`：最近 7 天内已有纪要内容的会议。
- 周报/工时扫描任务 `weekly-report-reminder` 已触发：
  - `project.weekly-report.due`：本周仍未填报周报/工时的项目成员。
  - `project.worklog.reminder`：本周仍未填报工时的项目成员。
  - `project.group.weekly-report`：按项目群推送项目成员数、任务完成数、逾期任务数、高风险数和本周工时汇总。
- 经营提醒扫描任务 `business-reminder-notification` 已触发：
  - `business.receivable.due`：回款计划日期在 7 天内，且未结清。
  - `business.receivable.overdue`：回款计划日期早于今天，且未结清。
  - `business.contract.closing`：项目已关闭但收入合同未收尾。
  - `business.invoice.exception`：发票状态包含异常、作废、退回或冲红。
  - `business.budget.variance`：预算执行存在超支或偏差比例不低于 10%。
  - `business.warning.detected`：经营预警 builder 识别出的利润、收尾、回款、SPI/CPI 风险。
- 经营报表分发任务 `business-report-distribution` 已触发：
  - `business.report.distribute`：每周生成项目经营、回款记录和经营预警报表摘要，模板可引用 `businessReport.fileName`、`businessReport.ledgerName`、`businessReport.rowCount`、`report.projectCount`、`report.receivableCount`、`report.warningCount`。

## 9. 同步任务导入格式

群同步任务 `SyncType=Group` 支持从任务配置或手动执行请求中传入：

```json
{
  "groups": [
    {
      "chat_id": "oc_xxx",
      "name": "项目 A 群",
      "projectId": "50000000-0000-0000-0000-000000000001",
      "projectName": "项目 A",
      "robotCode": "project-a-bot"
    }
  ]
}
```

会议记录同步任务 `SyncType=Meeting` 支持传入：

```json
{
  "meetings": [
    {
      "meeting_id": "meeting_xxx",
      "projectId": "50000000-0000-0000-0000-000000000001",
      "topic": "项目周例会",
      "meetingTime": "2026-06-26 10:00:00",
      "minutes": "已确认本周风险闭环计划。",
      "decisions": "下周完成 P1 风险处理。"
    }
  ]
}
```

说明：

- 外部群会写入 `IntegrationGroupBinding`；未传 `projectId` 时保持 `Pending`，后续人工绑定内部项目。
- 外部会议会写入 `ProjectMeetingRecord`，并通过 `IntegrationIdMapping` 记录外部会议 ID，避免重复同步。
- 当前导入格式用于打通同步任务链路；飞书、钉钉、企业微信真实群列表和会议列表 API 拉取仍需要真实租户权限验证。

## 10. 运维检查

每日检查：

- 连接器启用状态。
- 最近连接测试状态。
- 失败投递记录。
- 死信记录。
- 同步任务失败记录。
- Webhook 解析失败记录。

上线前检查：

- 公网回调域名证书有效。
- 反向代理未改写请求体。
- OpenAPI 出站访问可达。
- 租户连接器配置完整。
- 测试发送和手动同步通过。
- 失败重试和人工跳过入口可用。

## 11. 故障处理

| 故障 | 处理方式 |
|---|---|
| Token 获取失败 | 检查 AppId/AppSecret/AgentId、应用状态和平台权限 |
| 消息发送失败 | 查看投递日志、目标用户 ID、应用可见范围和平台错误码 |
| 同步失败 | 查看同步记录、接口权限、分页参数和部门根节点配置 |
| Webhook 验签失败 | 检查回调 Token/Secret、请求体是否被代理改写 |
| 回调重复 | 检查幂等键和平台事件 ID |
| 内网不可达 | 检查公网代理、DNS、证书和防火墙 |

## 12. 交付边界

- 本文是部署和运维说明，不替代真实平台联调。
- 真实验收必须使用目标企业租户配置完成。
- 钉钉、企业微信真实租户联调完成前，不得把对应 MVP 标记为完成。
- 飞书真实同步联调完成前，不得把飞书同步验收标记为完成。
