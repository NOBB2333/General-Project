# 前端预览技术选型文档

## 1. 背景

项目中文件管理模块需要支持多种文件格式的在线预览。当前已集成 `@flyfish-group/file-viewer3`（Flyfish File Viewer）作为前端预览组件。本文档对 Flyfish File Viewer 与 kkFileView（俗称"Open File View"）进行对比，为后续技术选型与演进提供依据。

## 2. 候选方案

### 2.1 Flyfish File Viewer（当前方案）

- **包名**：`@flyfish-group/file-viewer3`（legacy），新版本已迁移至 `@file-viewer/vue3`
- **类型**：纯前端 Vue 3 组件库
- **架构**：浏览器端直接解析渲染，无需后端转换服务
- **部署方式**：`npm install` 引入项目
- **开源协议**：Apache-2.0

### 2.2 kkFileView

- **项目地址**：[kekingcn/kkFileView](https://github.com/kekingcn/kkFileView)
- **类型**：后端在线预览服务
- **架构**：Spring Boot + LibreOffice，后端转换后返回 HTML/图片
- **部署方式**：独立服务器或 Docker 部署
- **开源协议**：Apache-2.0

## 3. 格式支持对比

| 格式类型 | Flyfish File Viewer | kkFileView |
|---------|---------------------|------------|
| Word | doc, docx | doc, docx, wps |
| Excel | xls, xlsx, xlsm, xlsb, csv, ods | xls, xlsx, csv, ods |
| PPT | pptx, ppsx | ppt, pptx, pps, ppsx |
| PDF | ✅ | ✅ |
| OFD（国产版式） | ✅ | ✅ |
| 图片 | png, jpg, gif, bmp, webp, svg, tiff, heic, psd, ai 等 | png, jpg, gif, bmp, tiff 等 |
| 音视频 | ✅ 原生 HTML5 | ✅ 原生 HTML5 |
| CAD/3D | dxf, dwg, glb, gltf, obj, stl, fbx, step, ifc 等 | dwg, dxf 等，3D 支持有限 |
| 压缩包 | zip, rar, 7z, tar, gz, iso 等 | zip, rar, 7z, tar 等 |
| 代码/文本 | 50+ 语言语法高亮 | 纯文本/代码高亮 |
| Markdown | ✅ | ✅ |
| EPUB 电子书 | ✅ | 有限 |
| 邮件 eml/msg | ✅ | eml |
| **格式总数** | 194+ 扩展名，23 条渲染管线 | 官方称 150+ 格式 |

> Flyfish 在 3D 模型、CAD 图纸、EPUB、邮件等小众格式上覆盖更广。

## 4. 使用方式对比

### 4.1 Flyfish File Viewer

```vue
<script setup>
import { FileViewer } from '@flyfish-group/file-viewer3'
import '@flyfish-group/file-viewer3/dist/file-viewer3.css'
</script>

<template>
  <FileViewer :file="fileObject" />
  <!-- 或 -->
  <FileViewer :url="fileUrl" />
</template>
```

- 直接作为 Vue 组件使用
- 支持传入 `File` 对象或 URL
- 全部解析渲染在前端完成

### 4.2 kkFileView

```vue
<template>
  <iframe
    :src="`https://kkfileview.xxx.com/onlinePreview?url=${encodeURIComponent(fileUrl)}`"
    width="100%"
    height="100%"
  />
</template>
```

- 通过 iframe 嵌入
- 需要先把文件上传到 kkFileView 可访问的地址
- 后端转换后返回预览页面

## 5. 预览形式与 UI 设计对比

| 维度 | Flyfish File Viewer | kkFileView |
|------|---------------------|------------|
| 预览容器 | 组件内嵌，可置于 Modal/Drawer/页面任意位置 | iframe 嵌入，独立页面感较强 |
| Office 预览效果 | 灰色工作台 + 白色纸张模拟，版式还原较好 | 转换为 HTML 后预览，版式可能略有偏差 |
| PDF 预览 | 基于 pdfjs，支持翻页/缩放/旋转 | 基于 pdfjs 或图片转换 |
| 图片预览 | 组件内支持缩放/翻转 | 独立图片查看器 |
| 主题适配 | 支持 light/dark 主题 | 主题较固定 |
| 水印 | 内置水印配置 | 支持全局水印 |
| 打印/下载控制 | 支持权限钩子 | 基础控制 |
| 移动端适配 | 响应式较好 | 一般 |

## 6. 性能与体验对比

| 维度 | Flyfish File Viewer | kkFileView |
|------|---------------------|------------|
| 首屏速度 | ✅ 快，无需后端转换 | ⚠️ 需后端转换，首次有延迟 |
| 大文件处理 | ✅ 按需异步加载 | ✅ 后端转换后可处理大文件 |
| 并发能力 | ✅ 无服务端压力 | ⚠️ 受服务器资源限制 |
| 离线可用 | ✅ 纯前端，可离线 | ❌ 依赖后端服务 |
| 网络依赖 | 只需能下载文件 | 文件 URL 需可被 kkFileView 访问 |
| 首包体积 | ⚠️ 较大（按需加载可缓解） | ✅ 前端几乎无体积 |

## 7. 运维与成本对比

| 维度 | Flyfish File Viewer | kkFileView |
|------|---------------------|------------|
| 服务器依赖 | ❌ 不需要 | ✅ 需要部署 Java 服务 |
| 资源占用 | 前端占用，无服务端成本 | 后端转换耗 CPU/内存 |
| 运维成本 | 低 | 中（需维护 LibreOffice/转换服务） |
| 授权费用 | 免费开源 | 免费开源 |
| 安全性 | 文件不离开当前系统 | 文件 URL 需暴露给 kkFileView |

## 8. 与项目场景匹配度

当前项目中的使用方式：

```vue
<FileViewer v-if="previewFileObject" :file="previewFileObject" />
```

该模式适用于：
- 文件管理系统
- 合同/审批预览
- 不想维护后端服务的场景
- 对首屏速度有要求的场景

若切换为 kkFileView：
1. 需要把文件暴露为 kkFileView 可访问的 URL；
2. 需要单独部署 kkFileView 服务；
3. 预览体验从"组件内嵌"变为"iframe 嵌独立页"；
4. 格式兼容性和大文件处理稳定性可能更优。

## 9. 选型建议

| 需求 | 推荐方案 |
|------|---------|
| 不想维护后端、快速集成 | Flyfish File Viewer |
| 对首屏速度敏感 | Flyfish File Viewer |
| 需要离线预览 | Flyfish File Viewer |
| 格式要求极其丰富（3D/CAD/EPUB/邮件） | Flyfish File Viewer |
| 文件已有公共 URL，不想前端解析 | kkFileView |
| 大文件、复杂 Office 文档稳定性优先 | kkFileView |
| 企业内部已有 Java 运维能力 | kkFileView |
| 需要在线编辑/多人协作 | 考虑 OnlyOffice |

## 10. 混合方案（推荐演进方向）

为兼顾纯前端的便利性与 Office 文档的稳定性，可采用组合策略：

```vue
<script setup>
const isOffice = computed(() => /\.(docx?|xlsx?|pptx?)$/i.test(fileName.value))
</script>

<template>
  <!-- Office 文档走 kkFileView/OnlyOffice -->
  <iframe
    v-if="isOffice && kkfileviewUrl"
    :src="kkfileviewUrl"
  />
  <!-- 其他格式继续走 Flyfish -->
  <FileViewer v-else :file="previewFileObject" />
</template>
```

该方案的优势：
- Office 文档由后端服务转换，预览更稳定；
- 其他格式仍由 Flyfish 在前端快速渲染；
- 无需为所有格式都部署后端服务。

## 11. 当前 Flyfish 使用中的注意事项

1. **包名已迁移**：`@flyfish-group/file-viewer3` 为 legacy 包，新项目建议迁移至 `@file-viewer/vue3`。
2. **版本较旧**：当前使用 `1.0.15`，新版可能包含 bug 修复与格式增强。
3. **Markdown 处理重复**：Flyfish 本身支持 Markdown 预览，项目中额外使用 `marked` 解析属于重复处理。
4. **缺少 fallback**：当 Flyfish 无法预览某种格式时，应提供"下载查看"等降级提示。

## 12. 结论

- 当前 Flyfish File Viewer 方案在**无需后端、首屏快、格式丰富**方面优势明显，适合项目现阶段需求。
- 若后续出现**大文件 Office 预览不稳定、版式偏差严重**等问题，可引入 kkFileView 作为 Office 文档的兜底或替代方案。
- 长期来看，**Flyfish 负责常规格式 + kkFileView/OnlyOffice 负责 Office 文档**的混合架构更具扩展性。
