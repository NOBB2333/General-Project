### 2.1 文件预览动态导入失败修复（P0）

#### 现象
点击项目文件预览时，浏览器控制台报错：

```
Failed to fetch dynamically imported module:
http://localhost:5677/node_modules/.vite/deps/md-B5xQUFBX.js?v=3f9f326e
```

实际 Vite 依赖目录中，`md-` 动态 chunk 当前 hash 是 `md-8mXYiXBb.js`，报错引用的 `md-B5xQUFBX.js` 是旧 hash。

#### 根因
`@flyfish-group/file-viewer3` 内部使用 `import()` 动态加载不同格式的解析器（例如 `md-*.js`、`umd-*.js`）。Vite 在开发模式下会对 `node_modules` 里的依赖做预构建（pre-bundle），但默认只扫描源码中的静态 / 动态 import，不会去分析已经预构建后的 bundle 里的动态 import。当依赖升级、缓存变化或 dev server 重启后，bundle 内部硬编码的 chunk hash 与 `node_modules/.vite/deps` 中实际存在的 chunk hash 不一致，就会报 404。

#### 解决方案
在 `vite.config.ts` 中把 `@flyfish-group/file-viewer3` 加入 `optimizeDeps.include`，让 Vite 把它作为整体预构建，并在 `umd` 等内部 chunk 变化时一并重新生成一致 hash。

**改动位置**

`General.Web/apps/web-general/vite.config.ts`

```ts
import { defineConfig } from '@vben/vite-config';

export default defineConfig(async () => {
  return {
    application: {},
    vite: {
      optimizeDeps: {
        include: ['@flyfish-group/file-viewer3'],
      },
      server: {
        proxy: {
          '/api': {
            changeOrigin: true,
            rewrite: (path) => path.replace(/^\//, ''),
            secure: false,
            target: 'https://localhost:44392/api',
            ws: true,
          },
        },
      },
    },
  };
});
```

> 注意：`@vben/vite-config` 的 `defineConfig` 会把传入的 `vite` 对象与默认配置合并。如果合并后未生效，需要排查 `node_modules/.vite/deps` 是否被缓存，可执行 `rm -rf node_modules/.vite` 后重启 dev server。

#### 备用兜底（验证方案后决定是否做）
若 `optimizeDeps.include` 仍无法消除动态 chunk 404，可在 `FilePreviewModal.vue` 中对 `FileViewer` 做懒加载错误捕获，提示用户刷新页面或下载文件，避免白屏。

#### 验收标准
1. 删除 `node_modules/.vite` 后启动 dev server；
2. 在项目详情 > 文档与知识中点击 `.docx`、`.xlsx`、`.pdf`、`.md` 等不同类型文件；
3. 控制台不再出现 `md-*.js` 或 `umd-*.js` 404；
4. 预览组件正常渲染。

### 2.4 排期筛选增加「当前排期」（P1）

#### 现状
`taskScheduleOptions` 当前只有：

- 全部排期
- 未排期
- 每个周期 / 冲刺的选项

#### 目标
增加「当前排期」选项，筛选逻辑：当前日期落在 `[startDate, endDate]` 区间内的周期 / 冲刺下的任务。

#### 改动点

`useProjectRequirements.ts`：

```ts
const taskScheduleOptions = computed(() => [
  { label: '全部排期', value: 'all' },
  { label: '当前排期', value: 'current' },
  { label: '未排期', value: 'unscheduled' },
  ...(detail.value?.cycles || [])
    .filter((item) => ['周期', '冲刺'].includes(item.type))
    .map((item) => ({
      label: `${item.type} · ${item.name} · ${item.status}`,
      value: item.id,
    })),
]);
```

`filteredTasks` 中新增分支：

```ts
if (taskScheduleFilter.value === 'current') {
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  const currentCycleIds = new Set(
    (detail.value?.cycles || [])
      .filter((item) => {
        const start = item.startDate ? new Date(item.startDate) : null;
        const end = item.endDate ? new Date(item.endDate) : null;
        return start && end && start <= today && end >= today;
      })
      .map((item) => item.id),
  );
  return scopedTasks.filter((item) => currentCycleIds.has(item.cycleId));
}
```

#### 验收标准

2. 选择后只展示属于当前日期所在周期的任务；
3. 没有当前排期时显示空状态。

### 2.5 排期（周期/冲刺）支持表格行内新建与编辑（P1，重点）

#### 主方案：ant-design-vue 可编辑行

##### 设计思路
- 表格始终保持一行「草稿行」在最底部；
- 草稿行所有可编辑列渲染为 `Input` / `Select` / `InputNumber`；
- 已有数据行点击「编辑」后进入行内编辑状态；
- 每行自带「保存 / 取消」操作；
- 使用 `row-class-name` 高亮编辑行和草稿行。

##### 数据模型
新增本地类型：

```ts
type CycleEditableRow = ProjectApi.CycleItem & {
  _isEditing?: boolean;
  _isDraft?: boolean;
  _form?: ProjectApi.ProjectCycleSaveInput;
};
```

> 复用现有 `cycleForm` 的字段结构，但把它作为每行的 `_form` 副本。

##### 表格列改造

`scheduleCycleColumns` 改为支持 `customCell` 或在 `bodyCell` 插槽中根据 `record._isEditing || record._isDraft` 判断渲染控件。

例如：

```vue
<template #bodyCell="{ column, record }">
  <template v-if="column.key === 'name'">
    <Input v-if="isEditing(record)" v-model:value="record._form.name" :maxlength="128" />
    <span v-else>{{ record.name }}</span>
  </template>
  <template v-else-if="column.key === 'type'">
    <Select v-if="isEditing(record)" v-model:value="record._form.type" :options="scheduleCycleTypeOptions" />
    <Tag v-else>{{ record.type }}</Tag>
  </template>
  <!-- 负责人、状态、父级、进度、日期、范围说明同理 -->
  <template v-else-if="column.key === 'actions'">
    <Space v-if="isEditing(record)">
      <Button size="small" type="primary" :loading="savingCycle" @click="handleSaveCycleRow(record)">保存</Button>
      <Button size="small" @click="handleCancelCycleRow(record)">取消</Button>
    </Space>
    <Space v-else>
      <Button size="small" type="link" @click="handleEditCycleRow(record)">编辑</Button>
      <Popconfirm title="确认删除？" @confirm="handleDeleteCycle(record.id)">
        <Button size="small" danger type="link">删除</Button>
      </Popconfirm>
    </Space>
  </template>
</template>
```

##### 交互流程
1. 页面加载时，`scheduleCycleRows` 末尾追加一条 `_isDraft: true` 的空行；
2. 用户填写草稿行后点击保存 → 调用现有 `createProjectCycleApi`；
3. 保存成功后刷新详情，重新生成草稿行；
4. 点击已有行「编辑」→ 把当前行数据复制到 `_form`，设置 `_isEditing: true`；
5. 保存时调用 `updateProjectCycleApi`；
6. 取消时恢复原值。

- 删除 `showCycleForm` 和 `cycleForm` 的全局表单状态；
- 删除「新增周期」「新增冲刺」按钮上方的表单区域；
- 保留两个按钮用于快速切换草稿行类型，但点击后直接在表格草稿行设置类型并聚焦。

#### 备用方案：表格顶部内联表单行

#### 验收标准

2. 已有行点击「编辑」后各字段变为输入控件；
